# BranchManager

**Microbial isolate assessment, marker-gene quality control, taxonomy,
novelty analysis and whole-genome sequencing prioritisation.**

BranchManager helps research groups manage isolate collections and make
more consistent, evidence-based decisions about which isolates should
progress to whole-genome sequencing (WGS).

It brings together Sanger chromatogram processing, marker-sequence
assembly and QC, reference-based taxonomy, project-baseline comparisons,
genome evidence and candidate-selection reports. It is designed to make
the evidence behind a recommendation visible and reviewable---not to
replace biological judgement.

> **Important:** A sequence with no close database match is not
> automatically novel. Poor read quality, short alignment coverage,
> mixed templates, contamination, missing references and unresolved
> taxonomy can all produce apparently unusual results. BranchManager
> keeps these evidence types separate and flags cases requiring review.

## What BranchManager does


| Area | What it provides |
|---|---|
| Sanger Studio | A local browser interface for inspecting AB1/ABI chromatograms, organising reads, reviewing assemblies and processing batches. ZIP archives containing nested folders of chromatograms can be uploaded directly. |
| Mailroom and Interview | Read inventory, sample-map preparation, chromatogram QC and resequencing triage. |
| Paper Trail | Trimming, quality assessment, read orientation, multi-read overlap assembly and consensus generation. |
| Taxonomic classification | Reference-based classification with identity, query coverage, reference coverage, supporting hits, assignment status and conflict reporting. |
| Novelty and baseline assessment | Comparisons against project baselines and configured external references, with explicit evidence and limitations. |
| Pangenome assessment | GTDB-derived taxonomic grouping, genome representation and target-gap reporting where the necessary evidence is available. |
| Genome evidence | Import and integration of genome-derived 16S and genome QC/taxonomy evidence. |
| Selection and reporting | Candidate panels, primary/backup recommendations, decision-focused SAB shortlists, quarterly review outputs and interactive HTML reporting. |
| Ground-truth validation | Create and approve checksummed reference snapshots, compare subsequent runs against approved baselines, detect workflow drift and generate validation reports. |
| Project profiles | Reusable JSON configuration for collection-specific paths, references, baselines and workflow defaults. |

BranchManager supports a staged workflow as well as the integrated
`assistant` command. You can run individual stages when you need to
inspect or repeat a particular part of the process.

## Installation

BranchManager requires **Python 3.12 or newer**.

### Conda is required

**Conda is required for the recommended BranchManager installation
methods.** It is used to create an isolated Python environment and
manage external bioinformatics dependencies such as VSEARCH, MAFFT and
FastTree.

If you do not already have Conda installed, we recommend installing
[Miniforge](https://github.com/conda-forge/miniforge), which provides
Conda with access to the conda-forge and Bioconda package repositories.

Download and install Miniforge for your operating system before
proceeding.

**Platform support:** Full BranchManager functionality is not currently
supported on Windows because some external software dependencies,
including FastTree, are not compatible with Windows. However,
**Sanger-Studio can be run on Windows** using the installation
instructions below.

### 1. macOS and Linux (recommended)

The cleanest installation option is to install BranchManager directly
from Bioconda:

``` bash
conda create -n branchmanager python=3.12 -y
conda activate branchmanager
conda install -c bioconda branchmanager -y
```

### 2. Windows (Sanger-Studio only)

Although the full BranchManager toolkit is not currently supported on
Windows, Sanger-Studio can be installed and run using Conda and pip:

``` bash
conda create -n branchmanager python=3.12 -y
conda activate branchmanager

python -m pip install branchmanager biopython
conda install -c bioconda vsearch -y
```

This provides the dependencies required to run Sanger-Studio. Other
BranchManager workflows may require additional software that is not
supported on Windows.

### 3. Alternative installation (pip and manual dependencies)

If the Bioconda installation is unavailable or unsuitable for your
environment, BranchManager can be installed using pip. This is the least
preferred option, as external dependencies must be installed separately.

First, create and activate a Conda environment:

``` bash
conda create -n branchmanager python=3.12 -y
conda activate branchmanager
```

Install the required external dependencies:

``` bash
conda install -c conda-forge biopython vsearch mafft fasttree -y
```

Then install BranchManager:

``` bash
python -m pip install --upgrade BranchManager
```

### 4. Check the installation

``` bash
branchmanager --version
branchmanager --help
```

See [Installation and dependencies](docs/installation.md) for optional
tools, external references and troubleshooting.

## Quick start

### Open Sanger Studio

``` bash
conda activate branchmanager
branchmanager sanger-studio
```

Sanger Studio starts a local web server and opens the interface in your
browser. It does not require input or output paths at startup.

You can select individual AB1/ABI files, choose an input directory, load
a sample map, or upload a ZIP archive containing chromatograms. ZIP
archives can contain nested directories; Sanger Studio searches them for
`.ab1` and `.abi` files.

For a full guide, see [Sanger Studio](docs/sanger-studio.md).

### Run the preflight checks

Before a production analysis, check the installation and project inputs:

``` bash
branchmanager it-desk -o preflight_check
```

The checks report the availability of required Python modules and
external executables. You can also provide project database, reference
and output paths to check those inputs.

### Run the integrated workflow

The `assistant` command is the standard end-to-end route for a partner
submission. A typical run uses a sample map, partner metadata, project
database, dataset label, reference database and output directory:

``` bash
branchmanager assistant \
  --sample-map ab1_mapping.tsv \
  --partner-metadata partner_metadata.tsv \
  --db project.db \
  --dataset Batch_01 \
  --ref gtdb_ssu_representatives.fna.gz \
  --threads 8 \
  -o runs/Batch_01
```

This is an illustrative command, not a complete project configuration.
Real runs will usually also specify baseline datasets, chimera-screening
references, taxonomy cross-checks, a Most Wanted List (MWL), and other
collection-specific settings. Use a project profile to avoid repeating
long sets of options.

See [Workflows and CLI commands](docs/workflows.md) and [Project
configuration](configs/README.md).

## The main workflow stages

  -----------------------------------------------------------------------
  Command                             Purpose
  ----------------------------------- -----------------------------------
  `mailroom`                          Inventory Sanger reads and prepare
                                      a validated read/sample map.

  `interview`                         Run standalone chromatogram QC and
                                      resequencing triage.

  `onboarding`                        Validate partner metadata and
                                      isolate identifiers.

  `paper-trail`                       Process reads, assess quality and
                                      assemble marker sequences.

  `filing-cabinet`                    Register baseline sequences and
                                      construct the reference backbone.

  `performance-review`                Classify marker sequences, assess
                                      novelty and update project
                                      evidence.

  `quarterly-review`                  Select a budgeted tranche of
                                      candidates from the project
                                      collection.

  `status-meeting` / `records-update` Import factual isolate and genome
                                      lifecycle information.

  `annual-report`                     Produce cumulative project
                                      reporting.

  `dashboard`                         Regenerate the interactive HTML
                                      dashboard from an existing run
                                      output directory.

  `assistant`                         Orchestrate the main
                                      submission-to-assessment workflow.

  -----------------------------------------------------------------------

Other commands support genome evidence imports, focused tree extraction,
iTOL annotation, marker review, MALDI metadata and project maintenance.

To regenerate the interactive dashboard from an existing run without
repeating the biological analyses:

``` bash
branchmanager dashboard /path/to/run_output
```

You can also provide the run's `assessment/` directory directly. The
command writes `performance_review_dashboard.html` into the run output
directory. See [Workflows and CLI
commands](docs/workflows.md#regenerate-an-existing-run-dashboard) for
input requirements and details.

Run `branchmanager --help` for the command list available in the
installed version.

## Ground-truth validation and workflow drift detection

BranchManager includes an optional validation toolkit for assessing
workflow consistency, detecting changes between runs and monitoring the
effects of software updates.

The toolkit allows users to establish an approved ground-truth reference
from a completed run and subsequently compare new runs against that
reference.

The validation workflow has three main commands:

  --------------------------------------------------------------------------
  Command                                Purpose
  -------------------------------------- -----------------------------------
  `branchmanager ground-truth init`      Create a checksummed, provisional
                                         reference snapshot from a completed
                                         run.

  `branchmanager ground-truth approve`   Explicitly approve a reviewed
                                         reference snapshot, recording the
                                         approver and reason.

  `branchmanager validate`               Compare a new run against an
                                         approved reference and report
                                         differences.
  --------------------------------------------------------------------------

Two validation modes are available:

-   `STRICT_REGRESSION`: Checks consistency against a fixed reference,
    identifying changes to outputs, decisions and workflow behaviour.
-   `PRODUCTION_COMPATIBILITY`: Accommodates legitimate changes in
    production cohorts while identifying unexpected differences in
    shared records and outputs.

Validation includes checks for:

-   Assessment, selection, novelty, marker-QC and manual review outputs.
-   Input provenance and SHA-256 checksums.
-   SQLite integrity, schema and database state.
-   Selection shortlist consistency and manual marker-review invariants.
-   Missing outputs, unexpected changes and workflow drift.

Reports are generated in JSON, TSV and HTML formats.

**Validation is optional and read-only.** It does not modify project
databases, biological analysis outputs or existing workflow execution
paths. New reference snapshots are provisional until explicitly
approved.

See [Ground-truth validation and workflow drift
detection](docs/validation-and-ground-truth.md) for the full guide,
including reference creation, approval and validation examples.

## How taxonomy and pangenome grouping work

BranchManager deliberately separates the partner's expected organism
group from sequence-derived taxonomic evidence.

-   The partner catalogue's `taxon` field is used for domain/pathway
    routing (for example, Bacteria or Archaea).
-   GTDB/reference taxonomy supplies the authoritative lineage used for
    pangenome grouping.
-   A missing or unresolved GTDB assignment remains unresolved; another
    classifier is not silently substituted as the pangenome authority.
-   The grouping rank follows the supported GTDB resolution. A reliable
    genus assignment does not have to be forced to species.
-   Pangenome eligibility also depends on the required reference-genome
    and tree context. Being routed through the bacterial workflow does
    not automatically make an isolate pangenome-eligible.

This distinction is important: a partner declaration of `bacteria` must
not merge unrelated bacterial genera into one pangenome group.

Read [Taxonomy and pangenome
interpretation](docs/taxonomy-and-pangenome.md) before interpreting
selection or gap reports.

## Project data and references

BranchManager is a workflow and decision-support toolkit; it does not
provide a universal, automatically current collection of taxonomic
references or project baselines.

A project should maintain and record the versions and provenance of its
own:

-   Reference FASTA files and associated taxonomy tables.
-   Cultured-isolate baseline FASTA files.
-   Partner metadata and isolate catalogue.
-   Genome assemblies and genome QC/taxonomy results.
-   Collection-specific anchors, where required.
-   Selection targets, thresholds and review decisions.

The repository includes example configuration files and templates. The
Rumen Gateway profile is an example of a configured project, not a
universal configuration for every collection.

## Scientific interpretation and limitations

BranchManager produces structured evidence and candidate
recommendations. These should be reviewed alongside the underlying
sequence data, metadata and biological context.

In particular:

1.  Identity is calculated over the aligned segment; it does not
    describe how much of the query or reference aligned.
2.  Query coverage and reference coverage must be considered separately.
3.  Taxonomic consensus and classifier confidence are not
    interchangeable with alignment identity.
4.  Novelty is relative to the configured project baselines and evidence
    sources; it is not a declaration of a new species.
5.  A pangenome gap is only meaningful when the relevant GTDB taxon and
    reference context are resolved.
6.  Recommendations are decision support. They do not replace isolate
    verification, genome QC, taxonomic review or experimental
    validation.
7.  A passing validation result establishes consistency with an approved
    reference; it does not independently establish that the reference or
    its biological conclusions are correct.

For details, see [Outputs and
interpretation](docs/outputs-and-interpretation.md).
