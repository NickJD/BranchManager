# BranchManager v1.0.0

**A major release focused on a more complete isolate-to-genome decision-support workflow.**

BranchManager v1.0.0 brings together the Sanger sequencing workflow, taxonomy and novelty assessment, genome evidence integration, pangenome reporting and candidate selection in a more consistent package.

This release is intended to make the evidence behind isolate prioritisation easier to inspect, reproduce and review.

## Highlights

### Sanger Studio

- Added a local browser-based Sanger Studio interface for chromatogram inspection and batch review.
- Supports AB1/ABI file selection, directory input and ZIP upload containing nested directories of chromatograms.
- Added multi-primer and multi-target workflow support, including 16S rRNA, ITS, 18S rRNA and 28S/LSU rRNA profiles.
- Improved chromatogram rendering, read alignment display, candidate-specific review and navigation between disagreements.
- Uses the existing Paper Trail processing and assembly engine rather than a separate base-caller or assembler.
- Retains QC and assembly evidence to support manual review and resequencing decisions.

### More explicit classification evidence

- Separates alignment identity from query coverage and reference coverage.
- Retains alignment length, supporting hits, taxonomy support and assignment status.
- Reports diagnostic-only matches separately from production classification evidence.
- Preserves taxonomic conflicts and the evidence behind consensus assignments.
- Avoids treating identity percentage as a classifier-supplied confidence score.

### GTDB-authoritative pangenome assessment

- Separates partner-catalogue domain/pathway routing from pangenome taxonomic identity.
- Uses GTDB-derived taxonomy as the authoritative source for pangenome grouping.
- Uses supported GTDB rank and lineage context rather than grouping solely by display name.
- Does not silently replace unresolved GTDB taxonomy with marker-classifier or partner-catalogue taxonomy.
- Preserves genus-level assessment where species-level evidence is not supported.
- Separates workflow routing, taxonomic assignment and pangenome eligibility.
- Aligns hierarchy eligibility with the evidence required for sequencing recommendations.

### Genome evidence integration

- Adds workflows for importing genome-derived 16S and genome evidence.
- Supports integration of GTDB-Tk and genome QC evidence where configured.
- Allows genome-only records to contribute to appropriate taxon-level representation counts when the required QC and GTDB evidence are available.
- Keeps genome-only records separate from marker alignments and marker-tree leaves.

### Reporting and selection

- Expands Performance Review reporting and interactive dashboard content.
- Improves pangenome hierarchy and coverage reporting.
- Adds clearer evidence and eligibility explanations to candidate review.
- Supports primary/backup candidate planning and later sequencing tranches.
- Retains factual isolate/genome status separately from recommendation status.

### Project configuration and command-line usability

- Adds reusable JSON project and Assistant profiles.
- Expands the CLI workflow and project lifecycle commands.
- Adds `branchmanager --version` and `branchmanager -v`.
- Keeps the package version as the single source for CLI version reporting.

## Installation

BranchManager requires Python 3.12 or newer.

Create and activate an environment:

```bash
conda create -n branchmanager python=3.12 -y
conda activate branchmanager
```

Install the external tools used by the standard marker workflow:

```bash
conda install -c conda-forge biopython vsearch mafft fasttree -y
```

Install the published release:

```bash
python -m pip install --upgrade BranchManager
```

Check the installation:

```bash
branchmanager --version
branchmanager --help
```

## Getting started

Open Sanger Studio:

```bash
branchmanager sanger-studio
```

Run the preflight checks:

```bash
branchmanager it-desk -o preflight_check
```

For a complete partner workflow, see the [main README](../../README.md) and [workflow guide](../workflows.md).

## Important interpretation notes

- A sequence with no close reference hit is not automatically novel.
- Identity must be interpreted alongside query coverage, reference coverage and alignment length.
- GTDB taxonomy is the pangenome grouping authority; partner `taxon` is used for domain/pathway routing.
- Unresolved GTDB taxonomy is not a confirmed pangenome gap.
- A sequencing recommendation is decision support, not a record of completed sequencing or a biological conclusion.

## Validation and release status

The release candidate includes targeted regression coverage for the new and corrected workflows. The full repository test suite should be run in the release environment before the GitHub release is published. Do not describe the full suite as passing unless it has completed successfully.

## Compatibility and project migration

Existing project databases and profiles should be backed up before upgrading. Review the current output schema and the taxonomy/pangenome interpretation guide before comparing results across versions. Re-run assessments where the updated taxonomy or eligibility rules change the interpretation of previous outputs.
