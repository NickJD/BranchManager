# BranchManager v1.1.0

## Added

### Ground-truth validation and workflow drift detection

- Added an optional, read-only ground-truth and workflow drift-validation toolkit.
- Added `branchmanager ground-truth init` to create checksummed, provisional reference snapshots from completed runs.
- Added `branchmanager ground-truth approve` for explicit, auditable approval of reviewed reference snapshots.
- Added `branchmanager validate` to compare assessment, selection, novelty, marker-QC and review-audit outputs against an approved reference.
- Added strict regression (`STRICT_REGRESSION`) and production compatibility (`PRODUCTION_COMPATIBILITY`) validation modes.
- Added SHA-256 input provenance verification, including reconciliation of historical input fingerprints against supporting workflow manifests when temporary intermediate files are no longer available.
- Added SQLite integrity, schema and database-state fingerprint checks.
- Added shortlist-subset, manual marker-review and other workflow invariant checks.
- Added JSON, TSV and HTML validation reports.
- Added supporting-manifest integrity checks to preserve the auditability of historical provenance evidence.

References are provisional by default and require explicit approval before they can be used as authoritative validation baselines. Validation is independent of the biological workflows and does not modify project databases or existing workflow outputs.

### SAB selection summary refinement

The SAB-facing `selection_summary.tsv` is now a decision shortlist rather than a row-for-row view of all assessed isolates.

- Reduced `selection_summary.tsv` to a 16-column decision-focused overview.
- Retained detailed classifier, novelty, pangenome and sequence evidence in `sequence_assessment.tsv` and supporting exports.
- Documented that the two TSVs are complementary rather than a strict superset/subset pair.

The shortlist includes isolates receiving a positive or provisional recommendation:

- `PRIORITISE - SET PRIMARY`
- `RESERVE - SET BACKUP`
- `STRONG CANDIDATE`
- `STRONG CANDIDATE - STRAIN DIVERSITY`
- `SECONDARY CANDIDATE`
- `SECONDARY - STRAIN DIVERSITY`
- `REVIEW BEFORE SELECTION`
- `REVIEW - PANGENOME BOUNDARY`

Already sequenced or committed isolates, baseline-redundant exclusions, no-marker resequencing cases, and lower-priority/no-added-value cases remain documented in `sequence_assessment.tsv` but are not included in the SAB shortlist.

The shortlist reports the partner, sampled host species, MWL ID and matched taxon, closest baseline genome ID and its GTDB taxonomy, baseline identity, and the NCBI, SILVA and GG2 taxonomy assignments. It also retains marker QC classification, evidence quality, recommendation and recommendation rationale.

The redundant `AlreadySelectedForGenomeSequencing` and `GenomeAlreadySequenced` columns have been removed. `MWLRole` is not included in the SAB-facing summary. `SABDecision` remains blank for the board to complete and can be imported using the existing status-meeting workflow.

## Retrospective sequencing decisions

- `selection_summary.tsv` includes a blank `SABDecision` column that the SAB can fill with `APPROVE`, `REJECT` or `DEFER`.
- `status-meeting` imports the returned summary directly and persists the decision as a sequencing commitment.
- A stale negative value in a cumulative partner catalogue no longer resets an existing SAB commitment; explicit deselection is recorded through `SABDecision=REJECT`.
- `records-update` marks a genome as sequenced when a genome record is registered, independently of whether genome QC passes.
- `branchmanager dashboard --db project.sqlite` overlays updated SAB decisions and genome records onto an existing dashboard without rerunning biological analyses. Pangenome target/gap calculations remain from the original assessment until the next Performance Review.
- A stale partner catalogue cannot erase a previously registered genome-availability fact.

## Version provenance

- Run manifests carry an explicit workflow version.
- Database inputs and outputs are inspected read-only for the applied SQLite schema migration version.
- The dashboard displays package, workflow and database schema versions, plus the database file SHA-256.
- Ground-truth references retain checksums for their recorded inputs and outputs, supporting reproducibility and comparison across software releases.
- Historical workflow manifests can provide supporting evidence for the checksums of temporary database states that are no longer present on disk.

## Compatibility

- Existing full assessment TSVs and older selection summaries remain readable by the dashboard.
- The SQLite schema is unchanged; this release uses schema migration version 6.
- Existing workflow commands and their execution paths are unchanged.
- Validation is opt-in and is not automatically invoked by biological workflows.
- Project databases are opened read-only during validation.
- Validation does not modify run outputs or database state; it writes reports only to the requested validation directory.
- New references are provisional by default and cannot be reported as an authoritative PASS until explicitly approved.
- Historical provenance reconciliation does not relax checksum requirements for mandatory biological inputs. Missing or altered required reference databases and metadata remain validation failures.
